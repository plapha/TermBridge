## 3. 设计要点与偏离

1. **订阅 API**：公开 `SessionManager::subscribe(session_id, from) -> Subscription`，
   `Subscription::is_resumed()` 区分重放/快照；`attach` 内部复用同一构造逻辑并返回 `resumed`。
2. **快照生成时机**：从 attach 时改为订阅第一次 `next()` 时生成。生成仍在同一把
   `Mutex<TerminalState>`（parser + 输出环 + scrollback + 模式记录）里完成，保证快照与
   `offset` 一致；`resumed` 判定仍在 attach 时完成，语义与任务书一致。
3. **ACK 路径**：`InputAck`/`InputRejected` 由接收端直接回给发送连接（不进 broadcast），
   避免其他订阅者收到无关噪声；客户端语义不变。
4. **控制权回收**：`SessionManager` 启动一个扫描线程（间隔 = grace/4，钳制在 20ms..1s），
   对每个会话检查宽限是否过期。宽限期可注入，用于测试。
5. **尺寸抖动**：快照挂接且当前处于备用屏、且挂接者取得控制权时，延迟 120ms 后
   `cols-1` → 恢复 `cols`（PTY 与 vt100 尺寸同步调整，不广播 `Resized`）。
6. **查询扫描**：状态机处理 CSI 参数/中间字节，识别 `?1004h/l`、`CSI Ps SP q`、
   `CSI 6n`、DA1；OSC 内容不会被当作查询误判。跨读取分片的序列可正确拼接。
7. **新增依赖**：无。
8. **偏离**：CLI/GUI 的“最小适配”仍保留单行输入框（M2/M3 按计划删除并与 raw 输入一起替换）；
   行模式 CLI 对 `busy` 拒绝没有重发缓冲（见第 6 节）。

## 6. 已知问题与风险

- **查询竞态（计划内）**：控制者在线时终端查询原样转发；若控制者恰好断线，或控制者是不会应答的
  CLI 行模式，查询无人应答。CLI raw 模式在 M3 处理；当前按任务书接受。
- **行模式 CLI 的 busy**：`InputRejected{busy}` 时只提示，不重发（1 MiB 队列下极难触发）；
  偏移重发缓冲属于 M4。
- **Windows 控制台在 Ctrl+C 时清空未处理输入**（测试中实测），客户端按键时序需在 M2 注意。
- **快照历史仍为纯文本**（M4 改为带颜色）；进入备用屏前的主屏内容无法恢复（3.3 已知降级）。
- **快照生成在锁内**：M1 历史上限 256 KiB，可接受；M4 扩大 scrollback 后需复核锁内耗时与分块策略。
- **写路径共享锁**：`Client::request` 与 `InputSender` 通过同一写锁串行；SSH 窗口满时输入会短暂排队，
  属于背压而非阻塞，M2 复核实际手感。
