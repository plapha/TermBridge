# M3 CLI Raw 模式 报告

## 1. 完成情况

- `session attach` 进入 raw 模式：Unix 用 `crossterm::terminal::enable_raw_mode`；Windows 用
  `windows-sys` 设置控制台模式（输入：`ENABLE_VIRTUAL_TERMINAL_INPUT`，去掉
  `ENABLE_LINE_INPUT | ENABLE_ECHO_INPUT | ENABLE_PROCESSED_INPUT`；输出：开启
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING | ENABLE_PROCESSED_OUTPUT`）。之后直接在 stdin 读原始字节，
  不使用 crossterm 事件 API。**已完成**。
- Ctrl+]（0x1d）本地转义：`d` 断开、`e` 结束（3 秒内再按一次确认）、`t` 接管、
  再按 Ctrl+] 发送字面 0x1d、其他键取消；进入 attach 时在 stderr 打印一行提示。**已完成**。
- 终端模式恢复：`RawModeGuard` 的 `Drop` + panic hook，正常退出、出错、panic 三条路径都会恢复
  （Windows 恢复原始输入/输出控制台模式）。**已完成**。
- 窗口尺寸：Unix 监听 SIGWINCH（`tokio::signal::unix`）；Windows 每 250 ms 轮询；
  只有控制者发送 `Resize`；挂接即控制、接管成功后立即发一次本地尺寸。**已完成**。
- 删除 `:detach` / `:end` / `:take` 行命令与按行发送逻辑；stdin 不是 TTY 时在连接前直接报错退出，
  不支持管道输入。**已完成**。
- 输出原始字节直接写 stdout；`SnapshotBegin` 先写清屏序列，快照分块原样输出；
  输出偏移缺口时自动按 `resume_from` 重新挂接。**已完成**。

## 3. 设计要点与偏离

1. **文件拆分**：按任务书允许的方式把 `crates/app/src/cli.rs` 拆为 `cli/mod.rs` +
   `cli/raw.rs`（`mod.rs` 只保留子命令与档案逻辑，raw 实现在 `raw.rs`）。
2. **新增依赖**：`crossterm = "0.28"`（Unix raw 模式与跨平台终端尺寸，允许列表内）；
   `windows-sys` 增加 `Win32_System_Console` feature（允许列表内，按需开启）。
3. **尺寸事件通道**：尺寸监听是独立任务，向 channel 发送新的 (cols, rows)，主 `select!` 只消费事件，
   避免平台分支写进主循环。
4. **结束确认**：`Ctrl+] e` 首次只提示，3 秒内再按一次才真正发送 `End`（任务书只要求「需要确认」，
   未规定形式）。
5. **已知竞态（实测发现）**：CLI 退出后的极短时间内，它的 stdin 线程仍阻塞在读取上，
   可能吃掉用户紧接着敲的第一个按键。端到端测试里以 1.2 s 等待规避；产品侧暂不处理（窗口极小），
   见第 6 节。
6. **范围外改动**：无。

## 5. 未验证项

- Claude Code / Codex / vim 的交互矩阵（需要人工在有真实终端的环境执行）。
- 真实控制台（非 ConPTY）下的视觉恢复效果；自动化通过 ConPTY 验证行为路径。
- Ctrl+Break / 强杀场景的终端恢复（原理上无法由进程自身恢复）。
- Linux / macOS 上的 raw 模式与 SIGWINCH（代码已实现，CI 会编译与跑单元测试，但没有 TTY 交互测试）。

## 6. 已知问题与风险

- **强杀不恢复**：进程被 Ctrl+Break 或任务管理器强杀时，Drop 与 panic hook 都不执行，
  控制台会留在 raw 模式；这是进程外清理问题，README（M10）建议用户用 Ctrl+] d 正常退出。
- **退出后第一个按键竞态**：见 3.5，窗口约毫秒级。
- **观察者的 Ctrl+] e**：非控制者按 Ctrl+] e 会被服务端拒绝并提示「未结束」。
- **IPC 输入过滤**：本地过滤只识别 Ctrl+]；其中 ESC 序列（方向键等）不受影响。
